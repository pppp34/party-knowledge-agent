# 党建知识库 Agent Web 应用 — 产品需求文档（PRD）

> 产品经理：许清楚（Xu） · 2026-05-29

---

## 1. 产品目标

构建一个面向基层党组织和党员的 **AI 驱动党建知识库 Web 应用**，整合党建知识检索、党员学习行为追踪、上下文对话与记录管理三大核心能力，通过 CodeBuddy Agent SDK 实现智能问答，支持与 WPS 文档生态互通，为党员学习和党建工作提供一站式数字化平台。

## 2. 用户故事

### 角色

| 角色 | 说明 |
|------|------|
| 党员 | 普通学习者，查询知识、学习课程、与AI对话 |
| 支部管理员 | 管理知识库内容、查看党员学习记录、导出报表 |
| 系统管理员 | 管理用户权限、系统配置、后台数据维护 |

### 核心用户故事

**US-1 党建知识库查询**
> 作为党员，我希望通过自然语言查询党建知识（如党章内容、组织生活制度、时政要点），系统能精准检索并返回相关内容，以便我快速获取权威解答。

**US-2 WPS 文档互通**
> 作为支部管理员，我希望能够将 WPS 云文档（金山文档）中的党建学习资料导入知识库，或将知识库内容导出为 WPS 文档，以便与现有办公流程无缝衔接。

**US-3 学习行为记录**
> 作为党员，我希望系统自动记录我的学习行为（查阅内容、对话时长、学习进度），以便形成个人学习档案。

**US-4 学习数据管理**
> 作为支部管理员，我希望查看本支部所有党员的学习行为汇总（学习时长、活跃度、知识掌握度），以便进行学习督促和考核依据。

**US-5 上下文对话**
> 作为党员，我希望与AI助手进行多轮上下文对话，系统保留完整对话历史，以便深入探讨党建知识。

**US-6 对话记录后台查询**
> 作为系统管理员，我希望在后台查询所有用户的历史对话记录（按用户、时间、关键词筛选），以便内容审计和学习质量评估。

## 3. 需求池

### P0 — MVP 必须

| 编号 | 需求 | 说明 |
|------|------|------|
| P0-01 | 党建知识库对话 | 基于 Agent SDK 的党建知识问答，预置党建领域 System Prompt |
| P0-02 | 多会话管理 | 创建、切换、删除对话会话，保留上下文 |
| P0-03 | 对话记录持久化 | SQLite 存储所有对话消息，重启不丢失 |
| P0-04 | 对话历史回放 | 点击历史会话可查看完整对话内容 |
| P0-05 | 学习行为记录 | 记录用户学习行为（对话次数、查询关键词、学习时长） |
| P0-06 | 管理后台-对话查询 | 管理员按用户/时间/关键词查询对话记录 |
| P0-07 | 用户登录认证 | 基础用户认证，区分党员/管理员角色 |

### P1 — 重要增强

| 编号 | 需求 | 说明 |
|------|------|------|
| P1-01 | WPS 文档导入 | 支持从金山文档导入党建资料到知识库上下文 |
| P1-02 | WPS 文档导出 | 支持将对话内容/知识摘要导出为 WPS 文档 |
| P1-03 | 知识库管理界面 | 管理员上传/编辑/删除知识库文档 |
| P1-04 | 学习数据看板 | 可视化展示党员学习行为统计（图表） |
| P1-05 | 党员学习档案 | 个人学习记录汇总页（对话历史、学习时长、知识点覆盖） |

### P2 — 未来迭代

| 编号 | 需求 | 说明 |
|------|------|------|
| P2-01 | 学习任务分配 | 管理员向党员推送学习任务 |
| P2-02 | 知识测验 | 基于知识库生成测验题目 |
| P2-03 | 移动端适配 | 响应式设计或小程序 |
| P2-04 | 知识库向量检索 | RAG 架构增强检索精度 |
| P2-05 | 多支部组织架构 | 支持多层组织结构管理 |

## 5. 待确认问题

| 编号 | 问题 | 影响 | 建议默认方案 |
|------|------|------|------------|
| Q-1 | WPS互通的具体交互方式？ | P1 需求实现路径 | MVP 先支持文档文件上传(.docx/.pdf)，P1 接入金山文档API |
| Q-2 | 用户认证方式？ | P0-07 实现方式 | MVP 先用本地用户名密码，后续可接 LDAP/企业微信 |
| Q-3 | 知识库数据来源？ | 核心功能范围 | MVP 用 System Prompt + 预置文档，P1 支持用户上传 |
| Q-4 | 学习行为记录的颗粒度？ | P0-05 数据模型 | 记录：会话时长、消息数、查询关键词、知识分类 |
| Q-5 | 是否需要多人在线实时协作？ | 架构复杂度 | MVP 单用户使用，后续支持多用户并发 |
| Q-6 | 部署环境？ | 技术选型 | 本地部署/内网部署为主，Docker 容器化 |
